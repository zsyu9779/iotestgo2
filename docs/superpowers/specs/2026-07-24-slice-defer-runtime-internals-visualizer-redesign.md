# Slice 与 Defer 运行时结构动画改版设计

## 1. 改版原因

现有 `module01_basics/visualizer/` 以精简代码、执行步骤和输出结果为主，
适合辅助理解示例代码，但没有把代码中看不到的内部数据结构完整展开。

本次改版将页面从“代码语义演示器”改为“运行时结构解剖实验室”：

- 不再以示例代码、高亮行或预测题组织课堂流程。
- 动画主体直接展示 Slice Descriptor、连续内存、函数栈帧和 `_defer`
  链表。
- 老师仍然逐步控制动画，每一步只解释一个内部操作。

现有四个场景将由两个更深入的实验室取代。

## 2. 真实性边界

### 2.1 Slice

Slice 实验室以项目当前环境 Go 1.25.11、darwin/arm64 为讲解基准。
页面展示与 `runtime.slice` 一致的三个字段：

```go
type slice struct {
    array unsafe.Pointer
    len   int
    cap   int
}
```

arm64 下指针和 `int` 均为 8 字节，因此教学舞台将 Descriptor 表示为连续的
三个机器字，字段偏移分别为 0、8、16，总大小为 24 字节。

页面中的十六进制地址是示意地址，不是浏览器读取到的 Go 进程真实地址。
字段布局、指针运算、长度和容量变化遵循上述实现。扩容路径使用真实 runtime
操作名称，但不把某个容量增长倍率描述为语言保证。

### 2.2 Defer

用户选择展示传统 `_defer` 链表模型，而不是现代编译器常见的 open-coded
defer。本页必须持续显示以下边界提示：

> 经典 `_defer` 链表实现模型。现代 Go 编译器可能使用 open-coded defer；
> 本实验室用于展开链表数据结构和注册、取出过程。

节点字段取自 Go 1.25.11 `runtime._defer`，课堂主体只展开传统路径需要理解的
字段：

- `heap`：记录是否位于堆上。
- `sp`：注册时的栈指针。
- `pc`：注册时的程序位置。
- `fn`：等待执行的函数值。
- `link`：指向更早注册的 `_defer`。

`rangefunc` 和 `head` 在结构检查器中列为“本场景不展开”，避免把删减后的卡片
误认成完整源码定义。

## 3. 信息架构

页面顶部只保留两个入口：

1. Slice Descriptor 与扩容。
2. `_defer` 链表与返回。

进入实验室后采用三栏结构：

- 左栏“结构检查器”：显示当前真实结构、字段偏移、字段值和字段说明。
- 中栏“运行时舞台”：显示连续内存、指针、栈帧、goroutine 和链表。
- 右栏“当前操作”：显示本步对应的 runtime 操作、输入、输出和一句解释。

底部保留讲师控制：

- 上一步。
- 重播本步。
- 下一步。
- 返回实验室目录。

不保留代码面板、执行行高亮、预测题和答案揭晓。

## 4. Slice 实验室

### 4.1 固定结构

结构检查器始终显示一个 24 字节 Descriptor：

| 偏移 | 字段 | 宽度 | 当前值 |
| --- | --- | --- | --- |
| `+0` | `array` | 8 B | 示意地址 |
| `+8` | `len` | 8 B | 当前长度 |
| `+16` | `cap` | 8 B | 当前容量 |

中间舞台显示：

- Descriptor 所在区域。
- 一段按元素宽度排列的连续内存。
- `array` 字段到首元素的指针。
- 每个元素的示意地址和偏移量。
- 长度边界与容量边界，两者使用文字和括号线共同表达。

右栏显示当前操作，例如：

```text
elementAddress = array + index × elementSize
```

### 4.2 步骤

1. **建立 Descriptor**
   - 创建 24 字节的三个字段。
   - `array` 指向连续数组首元素。
   - 显示 `len` 范围和 `cap` 范围。

2. **计算元素地址**
   - 选择一个元素。
   - 展开 `array + index × elementSize`。
   - 指针沿内存槽移动到目标元素。

3. **执行重新切片**
   - 旧 Descriptor 保持在舞台作为对照。
   - 生成新 Descriptor。
   - 新 `array` 等于旧指针加上 `low × elementSize`。
   - 新 `len = high - low`。
   - 新 `cap = oldCap - low`。
   - 两个 Descriptor 指向同一块连续内存的不同起点。

4. **容量足够的 append**
   - 计算 `newLen`。
   - 判断 `newLen <= cap`。
   - 直接写入当前内存的容量槽。
   - 只更新返回 Descriptor 的 `len`，不调用 `growslice`。

5. **容量不足，进入 growslice**
   - 展示 `newLen > oldCap`。
   - 当前操作切换为 `runtime.growslice`。
   - 输入展示 `oldPtr / newLen / oldCap / num / elementType`。

6. **计算新容量并分配**
   - 容量计算模块输出 `newCap >= newLen`。
   - 不固定显示某个倍率。
   - `mallocgc` 创建新的连续内存区域。

7. **复制旧元素**
   - `memmove` 按字节复制旧元素。
   - 新元素写入新数组的追加位置。
   - 复制进度按内存槽逐步高亮。

8. **返回新 Descriptor**
   - `array` 改为新内存地址。
   - `len` 改为 `newLen`。
   - `cap` 改为计算后的 `newCap`。
   - 旧 Descriptor 仍指向旧内存。
   - 旧内存仅在不可达后才有资格被 GC 回收。

## 5. Defer 实验室

### 5.1 固定结构

舞台包含三个区域：

- 当前 goroutine，其中保存 `_defer` 链表头指针。
- 当前函数栈帧，其中显示 `SP` 和返回位置。
- `_defer` 节点内存区，按链表链接多个节点。

每个节点展开为字段表：

| 字段 | 本实验室中的作用 |
| --- | --- |
| `heap` | 标记节点分配位置 |
| `sp` | 绑定注册它的函数栈帧 |
| `pc` | 保存注册时的程序位置 |
| `fn` | 保存等待执行的函数值 |
| `link` | 指向更早注册的节点 |

### 5.2 步骤

1. **进入函数栈帧**
   - goroutine 的 `_defer` 头指针为空。
   - 当前函数栈帧显示 `SP` 和返回地址。

2. **注册第一个 defer**
   - 创建节点 D1。
   - 填充 `sp / pc / fn`。
   - `D1.link = nil`。
   - goroutine 头指针改为 D1。

3. **注册第二个 defer**
   - 创建节点 D2。
   - `D2.link = D1`。
   - goroutine 头指针改为 D2。
   - 页面用地址和箭头表达链表，而不是抽象卡片堆。

4. **进入 deferreturn**
   - 函数正常返回路径进入 `deferreturn`。
   - 根据当前栈帧的 `SP` 查找属于该帧的头结点。

5. **取出并执行 D2**
   - 保存 `D2.fn`。
   - 头指针移动到 `D2.link`。
   - D2 从链表脱离。
   - 调用保存的函数值。

6. **取出并执行 D1**
   - 重复相同过程。
   - 头指针最终变为 `nil`。

7. **完成函数返回**
   - 当前栈帧没有待执行节点。
   - 恢复正常返回流程。
   - 定格解释：LIFO 是链表头插、链表头取出的直接结果。

8. **异常返回入口**
   - 只显示 panic 路径也会遍历待执行记录。
   - 不展开 `_panic`、`recover` 或多次 panic 状态机。

## 6. 视觉与动画规则

- 真实结构字段使用等宽字体和固定字节网格。
- 所有地址同时显示符号名，例如
  `0x1000 · backingArray[0]`，防止学生只记十六进制数字。
- 指针必须连接到具体内存对象，不允许只写“指向 index”。
- 当前读取、当前写入、新分配和已脱链使用不同形状及文字标签，颜色不是唯一
  区分手段。
- 每一步由完整状态渲染，不依赖上一步动画结束后的 DOM 残留。
- 单步动画不超过 900 ms，不自动播放下一步。
- `prefers-reduced-motion` 下立即呈现该步最终结构。
- 1280×720 和 1440×900 使用三栏；390×844 改为检查器、舞台、操作面板纵向
  排列，不产生横向页面溢出。

## 7. 技术设计

继续使用无构建依赖的 HTML、CSS 和经典 JavaScript：

- `index.html`：离线入口。
- `styles.css`：内存网格、指针连线、栈帧和响应式布局。
- `scenes.js`：两个实验室的声明式内部状态。
- `app.js`：纯状态机、结构渲染器和讲师控制。
- `tests/`：结构契约、每一步渲染、控制器和离线壳测试。

不执行 Go 代码，不读取进程内存，不使用 `eval`，不加载外部资源。页面展示的
结构值来自经过核对的声明式步骤数据。

## 8. 验收标准

- 首页只有 Slice 和 Defer 两个运行时实验室入口。
- 页面不再出现示例代码面板、预测题或输出结果教学流程。
- Slice Descriptor 明确显示 24 字节、三个字段和偏移。
- 重新切片过程完整展示指针、长度和容量公式。
- append 两条路径明确区分是否调用 `runtime.growslice`。
- 扩容过程依次展示容量计算、`mallocgc`、`memmove` 和新 Descriptor。
- `_defer` 节点展示 `heap / sp / pc / fn / link`。
- 两次注册后形成 `D2 → D1 → nil`，返回时按头结点依次移除。
- Defer 页面持续显示经典链表模型的版本边界提示。
- 上一步、下一步、重播和返回目录均可用。
- 页面离线可打开，三档目标视口无横向溢出，并支持减弱动画。
