# Module01 Slice 与 Defer 原理动画页设计

## 1. 背景与目标

`module01_basics` 已通过 Go Demo 讲解 Slice 的共享与扩容行为，以及
`defer` 的逆序执行和求值时机。终端输出可以证明结果，但不容易在课堂上展示
“结果为什么发生”。

本功能增加一个无需后端和网络的静态教学页面，供讲师在课堂投屏时逐步播放。
页面使用精简示例，不直接执行 Go 代码，而是通过经过核对的声明式步骤数据，
同步展示代码位置与底层概念模型。

成功标准：

- 讲师可以自行控制每一步，不发生自动连播。
- 学生能看出 Slice Header 与底层数组的关系。
- 学生能区分 `append` 复用原数组和重新分配后的共享关系。
- 学生能看出 `defer` 的注册与逆序执行过程。
- 学生能区分普通参数的注册时求值与闭包体的执行时读取。
- 页面可离线打开，并支持按钮和键盘操作。

## 2. 范围

### 2.1 第一版包含

页面包含四个独立场景：

1. Slice 子切片共享底层数组。
2. Slice 在容量有余和容量已满时执行 `append`。
3. 多个 `defer` 的注册与 LIFO 执行。
4. `defer` 普通参数与闭包的不同读取时机。

每个场景都遵循统一课堂流程：

1. 进入场景。
2. 观察初始状态。
3. 在关键变化前预测结果。
4. 由讲师揭晓并逐步播放变化。
5. 定格一句可带走的结论。

### 2.2 第一版不包含

- 在线执行或编辑 Go 代码。
- Slice `copy`、nil Slice 或完整 Slice 表达式。
- `panic`、`recover`、命名返回值修改等 Defer 扩展主题。
- 测验计分、学习进度保存、后端接口或用户系统。
- 对 Go 运行时内部地址、扩容倍率或某种编译器实现作固定承诺。

## 3. 页面结构

页面采用单页、四场景结构。

顶部为场景导航，分为 Slice 和 Defer 两章。主区域使用“动画舞台优先”的双栏：

- 左侧约占 34%，显示精简代码并高亮当前执行行。
- 右侧约占 66%，显示 DOM/SVG 动画舞台。
- 主区域下方显示当前步骤、讲师提示和进度。
- 页面底部提供上一步、重播本步和下一步。

宽屏以 16:9、1280×720 投屏为主要目标。窄于桌面断点时，代码区和动画舞台
上下排列，控制按钮允许换行但不能遮挡内容。

页面使用深色高对比主题。颜色只表达稳定含义：

- 当前执行位置。
- 共享引用或同一存储区域。
- 新分配的存储区域。
- 已注册、当前执行和已执行的 Defer 调用。

颜色不是唯一信息来源；所有状态同时通过标签、连线、形状或文字表达。

## 4. Slice 动画设计

### 4.1 场景一：共享底层数组

精简代码：

```go
base := []int{1, 2, 3, 4}
view := base[1:3]
view[0] = 9
fmt.Println(base)
```

步骤：

1. 创建 `base`。舞台出现一个 Slice Header 和底层数组 `[1 2 3 4]`。
2. 创建 `view`。出现第二个 Header，其指针连到原数组下标 1；分别显示两个
   Slice 的 `len` 和 `cap`。
3. 进入预测页：修改 `view[0]` 后，`base` 是否变化。
4. 揭晓后将底层数组中的 `2` 变为 `9`，两条指针保持不动。
5. 同时标出 `base[1]` 与 `view[0]` 对应同一个数组单元。
6. 定格结论：Slice Header 是独立的值，底层数组元素仍然可以共享。

页面把 Slice Header 显示为“指针、len、cap”的教学模型，但不声称用户代码
可以依赖某种运行时内存布局或具体地址。

### 4.2 场景二：append 复用与重新分配

精简代码：

```go
spare := make([]int, 2, 4)
reused := append(spare, 3)

full := make([]int, 2, 2)
grown := append(full, 3)
```

舞台并排展示两条轨道：

1. 建立“容量有余”和“容量已满”的初始状态。
2. 容量有余轨道执行 `append`：新元素落入原数组可用槽位，返回 Slice 的
   `len` 增加并继续指向原数组。
3. 进入预测页：容量已满时能否继续写入原数组。
4. 揭晓后出现一个更大的新数组，原有元素以连续运动复制到新区域，新元素落位。
5. `grown` 指向新数组，`full` 仍指向旧数组。
6. 分别修改新旧数组中的对应元素，直观验证两者不再共享该存储。
7. 定格结论：`append` 返回的新 Slice 是否继续共享底层数组，取决于容量是否
   足够；调用方必须接收返回值。

新数组容量只显示为“容量不小于新长度”，不展示固定翻倍规则。复制动画表达
元素被复制到新的存储区域，不用于说明垃圾回收或地址变化的具体时刻。

## 5. Defer 动画设计

### 5.1 场景三：注册与 LIFO

精简代码：

```go
func work() {
    defer print("A")
    defer print("B")
    print("work")
}
```

步骤：

1. 进入 `work`，概念性的待执行区为空。
2. 执行第一个 `defer`，A 卡片进入待执行区。
3. 执行第二个 `defer`，B 卡片位于 A 上方。
4. 进入预测页：函数结束时先输出 A 还是 B。
5. 执行 `print("work")`，随后到达“准备返回”关口。
6. B、A 依次弹出并执行，最后离开函数。
7. 定格结论：后注册的 Defer 调用先执行。

### 5.2 场景四：参数快照与闭包读取

精简代码：

```go
value := 1
defer print(value)
defer func() { print(value) }()
value = 2
```

步骤：

1. 创建变量格 `value = 1`。
2. 注册普通调用。页面显示函数值和参数已经求值，卡片保存 `arg = 1`。
3. 注册闭包调用。卡片显示“函数体执行时读取 value”。
4. 变量格变化为 `value = 2`。
5. 进入预测页：两个调用分别输出什么。
6. 闭包调用先执行并读取 2；普通调用随后输出保存的 1。
7. 定格结论：`defer` 语句执行时，函数值和调用参数立即求值；闭包体在真正
   执行时才读取它访问的变量。

### 5.3 语义模型与实现边界

主动画解释 Go 语言保证的可观察行为。“待执行卡片栈”是语义模型，不宣称所有
编译结果都会分配相同的运行时节点。结尾注解说明编译器可以采用开放编码、
栈上记录或其他优化，只要不改变上述可观察结果。

## 6. 交互与状态流

应用状态至少包含：

- 当前场景 ID。
- 当前步骤索引。
- 当前预测选择。
- 预测是否已揭晓。
- 当前动画是否进行中。

场景数据只描述代码、步骤、舞台状态、讲师提示和预测题。渲染器根据完整状态
更新 DOM/SVG，不依赖上一步留下的临时 DOM。因此前进、后退、重播或切换场景
都得到确定结果。

交互规则：

- 右方向键或空格：下一步。
- 左方向键：上一步。
- `R`：重播当前步。
- 预测步骤必须先选择一个答案，再允许揭晓。
- 揭晓和进入下一步是两个独立动作，给讲师留下解释时间。
- 动画执行期间暂时锁定翻页，避免快速连按导致状态竞争。
- 首步禁用“上一步”。
- 末步的“下一步”变为“返回场景目录”。
- 切换场景时清除预测选择和临时动画状态。

使用原生按钮并保留清晰焦点样式。键盘事件在按钮聚焦时不能造成重复触发。

## 7. 技术结构

第一版采用无构建依赖的 HTML、CSS 和 JavaScript，文件放在
`module01_basics/visualizer/`：

- `index.html`：语义化页面骨架和静态入口。
- `styles.css`：投屏布局、主题、状态样式与动画。
- `scenes.js`：四个场景的声明式步骤数据。
- `app.js`：状态机、键盘控制、DOM/SVG 渲染和动画协调。

页面不使用 `eval`，不加载外部 CDN，不需要 Go 服务进程，也不持久化任何
浏览器数据。直接打开 `index.html` 即可使用。

DOM 负责代码、标签、数组单元和 Defer 卡片。SVG 只负责跨区域指针、连线和
移动路径。这样既能表达空间关系，又能保持文字清晰和可访问。

## 8. 动画与可访问性

- 单步动画持续约 400–700 毫秒，不自动连播、不循环播放。
- 状态变化使用移动、翻转或沿路径复制，避免只用淡入淡出。
- 支持 `prefers-reduced-motion: reduce`，启用时立即切换到目标状态。
- 当前代码行、预测结果和结论使用可见文字，不能只依赖颜色。
- 关键舞台提供简短的屏幕阅读器描述。
- 页面缩放到 200% 时，控制区和正文仍可操作。

## 9. 异常与边界处理

- 找不到场景或步骤时回到场景目录，并显示可理解的错误提示。
- 渲染器无法找到目标元素时停止当前动画，恢复控制按钮，不留下锁死状态。
- 动画取消或场景切换时清理定时器和过渡监听。
- 快速键盘输入在动画锁期间被忽略，而不是排队批量执行。
- 页面不依赖网络资源，因此不存在课堂网络失败降级路径。

### 10.2 页面行为

使用浏览器自动化和人工检查覆盖：

- 上一步、下一步、重播、预测和揭晓符合状态机约束。
- 左右方向键、空格和 `R` 正常工作且不会重复触发。
- 快速点击、动画中按键、切换场景后不会产生错位或锁死。
- 重新加载页面回到确定的初始状态。
- 关闭网络后直接打开本地入口仍可使用。

### 10.3 视觉检查

在至少以下视口渲染并截图检查：

- 1280×720：课堂投屏主视口。

检查代码、连线、数组单元、Defer 卡片、讲师提示和控制按钮无重叠、裁切或
横向溢出；检查减少动态效果模式下的最终状态与普通模式一致。
