# Task Manager 一周作业

这是 Module 01 的课后一周作业，不是课堂综合项目。请在自己的开发分支上完成内存版任务管理器，并让统一验收脚本全部通过。本目录可以直接复制到 Gitee 仓库根目录；代码只能使用 Go 标准库，并须兼容 Go 1.16。

## 学习目标

- 用结构体和方法表达一个小型业务模型。
- 用切片维护有顺序的内存状态。
- 正确处理输入清洗、业务错误和不存在的 ID。
- 理解“返回副本”如何保护对象内部状态。
- 使用 `gofmt`、`go vet`、测试和构建形成最小交付闭环。

## 必须实现的行为

请保留 `taskmanager` 包已经给出的公开类型、错误变量和方法签名：

```go
NewManager() *Manager
Add(title string) (Task, error)
List() []Task
Complete(id int) (Task, error)
Delete(id int) error
```

实现须满足以下规则：

1. `Add` 使用 `strings.TrimSpace` 清理标题；清理后为空时返回 `ErrEmptyTitle`，且不新增任务。
2. 第一条任务 ID 为 `1`，之后严格递增。删除任务后不复用旧 ID。
3. 新任务的 `Completed` 为 `false`；`List` 按添加顺序返回全部任务。
4. `List` 和其他公开方法返回的数据不能让调用者修改管理器内部保存的任务。
5. `Complete` 把指定任务标记为完成并返回更新后的副本；未知 ID 返回 `ErrTaskNotFound`。
6. `Delete` 删除指定任务；未知 ID 返回 `ErrTaskNotFound`。

起始代码中的 `ErrNotImplemented` 只用于标记尚未完成的方法。你需要逐步替换这些返回值，直到验收通过。

## 本次不做

- 不做文件、数据库或云端持久化。
- 不做网络 API、网页界面、登录和权限系统。
- 不要求并发安全、排序、搜索、截止日期或优先级。
- 不使用第三方依赖、泛型或 Go 1.16 之后才提供的语法和 API。
- 不修改公开方法签名、公开测试、验收脚本或流水线来绕过检查。

## 四个里程碑

1. **第 1～2 天：读懂契约。** 运行测试，阅读 `Task`、`Manager` 和公开测试，列出每个方法的输入、输出与错误。
2. **第 3～4 天：完成核心行为。** 依次实现 `Add`、`List`、`Complete`、`Delete`，每完成一个行为就运行 `go test ./...`。
3. **第 5～6 天：处理边界和 CLI。** 检查空标题、未知 ID、ID 递增与返回副本；手动体验 CLI 的全部命令。
4. **第 7 天：提交前验收。** 运行 `make grade`，确认格式、Vet、测试和构建全部通过，再推送开发分支。

## CLI 命令和示例

CLI 支持 `add <标题>`、`list`、`complete <ID>`、`delete <ID>` 和 `exit`。命令与参数之间可以使用空格或 Tab 等空白字符，标题可以包含空格；ID 必须是整数。`list` 和 `exit` 不接受参数，`complete` 和 `delete` 只接受一个 ID；参数数量不正确时会显示用法提示。

```text
> add  写公开测试
已添加：1 [ ] 写公开测试
> list
1 [ ] 写公开测试
> complete 1
已完成：1 [x] 写公开测试
> delete 1
已删除任务 1
> list
暂无任务
> exit
再见！
```

CLI 用于人工检查命令解析和输出；自动评分以 `scripts/grade.sh` 执行的检查为准。
